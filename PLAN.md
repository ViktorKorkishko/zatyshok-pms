## Ціль

Робоча серверна частина системи «Затишок», на якій через Swagger демонструється
повний цикл: пошук доступності → створення бронювання гостем і оператором →
підтвердження → заселення з призначенням номера → додаткова послуга і платіж →
виселення → автоматичне завдання на прибирання → виконання прибирання → номер
знову вільний. Усе — з перевіркою ролей і області видимості, історією змін,
журналом аудиту, автоматичними тестами і документованим API.

   номери, тарифи, послуги, ролі та тестових користувачів кожної ролі.
2. Реалізовані всі функціональні вимоги з пріоритетом M із модулів: адміністрування
   (FR-01–FR-05), номерний фонд (FR-06–FR-09), бронювання (FR-10–FR-18), прийом та
   розміщення (FR-19, FR-20, FR-22), гості (FR-23, FR-24), обслуговування номерів
   (FR-27–FR-30), розрахунки (FR-31, FR-33), сповіщення (FR-39 — через Outbox, реальне
   надсилання через локальну SMTP-заглушку). Вимоги S: FR-13, FR-21, FR-25, FR-26,
   FR-32, FR-37 — якщо лишається час після M. Звітність (FR-35, FR-36) — мінімум:
   завантаження і дохід за період по готелю.
3. Кожен ендпоінт має XML-коментар і відображається в Swagger із прикладами; помилки
   повертаються у форматі ProblemDetails українською.
4. `dotnet test` зелений: юніт-тести доменних правил (переходи станів усіх чотирьох
   сутностей, розрахунок вартості з сезонними тарифами, формула доступності) +
   інтеграційні тести API проти реальної PostgreSQL у Testcontainers, включно з тестом
   на два одночасні бронювання останнього номера (один має отримати 409).
5. Історія git: кожна задача — гілка `feature/*` і PR у `main`; коміти Conventional

6. `PLAN.md`, розділ «Журнал помилок»: усі баги, знайдені під час розроблення і

### T1 — Фундамент БД (`feature/db-foundation`)

- `docker-compose.yml`: PostgreSQL 16 (порт 5432, БД `zatyshok`), `.env.example`
  з dev-логіном/паролем, `.env` у .gitignore; сервіс smtp4dev для перегляду листів
  (web UI на порту 8025, SMTP — 1025).
- Пакети: `Npgsql.EntityFrameworkCore.PostgreSQL` (Infrastructure),
  `Microsoft.EntityFrameworkCore.Design` (Api); `dotnet-ef` як локальний tool
  (`dotnet new tool-manifest`).
- `ZatyshokDbContext` в Infrastructure; реєстрація в Api; рядок підключення з
  конфігурації (`appsettings.Development.json` без пароля, пароль — з `.env`/user-secrets).
- Сутності модуля Rooms у `Domain/Modules/Rooms`: `Hotel`, `RoomCategory`, `Room`
  + enum `RoomStatus`, `Rate`, `SeasonRate`. Fluent-конфігурації в
  `Infrastructure/Modules/Rooms`. Індекси: унікальність `(HotelId, Number)` для Room;

- Міграція `InitialRooms`. Seed у Development: 5 готелів з таблиці 5.1 docs/02,
  категорії Standard/Superior/Suite, 3–5 номерів на готель, базові тарифи,
  2 сезонні періоди.
- `GET /health` з перевіркою БД. README: запуск з нуля.
- DoD: `dotnet build`, міграція застосовується на чисту БД, /health = Healthy,

## Технічні рішення

Зафіксовані — не змінювати без обговорення з командою.

- REST: префікс `/api/v1`, іменники у множині (`/api/v1/bookings/{id}/check-in`),
  DTO окремо від сутностей, `ProblemDetails` для помилок (400 валідація, 401/403,
  404, 409 конфлікт стану/доступності), пагінація `page/pageSize` для списків.
- Без MediatR та інших сторонніх бібліотек для подій/CQRS — простий власний диспетчер.
- **Валідація: FluentValidation** (зафіксовано в T1): доменні правила з датами
  (виїзд пізніше заїзду, заїзд не раніше сьогодні) і умовні перевірки простіше
  виразити та покрити юніт-тестами, ніж через DataAnnotations.
- Транзакції — явні (`BeginTransactionAsync`) у прикладних сервісах для операцій,
  що змінюють кілька сутностей; ізоляція ReadCommitted + блокування рядка
  `FOR UPDATE` для доступності.
- Тести: xUnit + FluentAssertions; інтеграційні — `WebApplicationFactory` +
  `Testcontainers.PostgreSql`; без InMemory-провайдера EF (не відтворює транзакцій
  і блокувань).
- **Ідентифікатори: `Guid` v4 через `Guid.NewGuid()`, створюються в коді**
  (зафіксовано в T1: v7 у .NET 8 недоступний без сторонніх бібліотек; тип колонки —
  Npgsql `uuid`).
- **SMTP-заглушка: smtp4dev** (зафіксовано в T1: активно підтримується, web UI на
  8025, SMTP на 1025; MailHog не розвивається з 2020 року).
- Логування — вбудоване `ILogger`; кожен запит із `CorrelationId`.
- Ніяких UI-бібліотек і клієнтського коду в цьому етапі.

## Журнал помилок

Кожен баг фіксується одразу при виявленні, у тому числі власні помилки розробки.
Формат запису:

> **№. Назва** — дата.
> - **Опис:** що не так.
> - **Кроки відтворення:** як побачити.
> - **Очікуваний / фактичний результат.**
> - **Причина:** корінь проблеми.
> - **Виправлення:** коміт `fix: …` (hash).

> **1. Zatyshok.Api.http посилався на видалений шаблонний ендпоінт** — 2026-09-09 (T1).
> - **Опис:** файл `src/Zatyshok.Api/Zatyshok.Api.http` містив запит `GET /weatherforecast/` зі стандартного шаблону ASP.NET Core, хоча контролер WeatherForecast у T1 видалено.
> - **Кроки відтворення:** відкрити `Zatyshok.Api.http` у Rider/VS, виконати запит.
> - **Очікуваний / фактичний результат:** запит до реального ендпоінта / завжди 404.
> - **Причина:** залишок шаблону після чищення WeatherForecast; знайдено багатоагентним рев'ю diff-у T1.
> - **Виправлення:** `fix: point api http file at health endpoint` (97d8efd) — запит замінено на `GET /health`.

> **2. Seed обіцяв фіксовані id, але id номерів/тарифів були випадковими** — 2026-09-09 (T1).
> - **Опис:** коментар `DevelopmentDataSeeder` стверджував, що всі id фіксовані для стабільних тестів, але фіксованими були лише готелі й категорії; Room/Rate/SeasonRate отримували новий `Guid.NewGuid()` при кожному засіванні.
> - **Кроки відтворення:** `docker compose down -v`, `docker compose up -d`, міграція, запуск API двічі — id номерів у БД різні між запусками.
> - **Очікуваний / фактичний результат:** однакові id після скидання БД / нові id щоразу; тест T3, який захардкодив би id тарифу, зламався б після скидання.
> - **Причина:** ініціалізатор `Id = Guid.NewGuid()` у сутностях не перекривався в seed для 42 з 50 рядків; знайдено рев'ю diff-у T1.
> - **Виправлення:** `fix: make seeded ids deterministic across database resets` (108726f) — детерміновані id `3333…{готель}{номер}`, `4444…{готель}{категорія}`, `5555…{01,02}`.

> **3. Команда скидання БД у README не працювала в Windows PowerShell 5.1** — 2026-09-09 (T1).
